## 🧭 Overview

Every subscription business loses revenue to churn — the question isn't just *who's leaving*, but *who's worth trying to keep*. This project builds an end-to-end churn prediction system on the [IBM/Kaggle Telco Customer Churn dataset](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) (7,043 customers), then turns that model into two things a retention team could actually use:

- An **exploratory dashboard** showing which customer segments churn most, and why
- A **prediction tool** that scores individual customers or entire uploaded lists, with plain-language reasoning for each score

## ✨ Features

- **11 engineered features** beyond the raw dataset — tenure buckets, service bundling counts, contract risk scoring, spend interactions
- **4 trained models** (Logistic Regression, Random Forest, XGBoost, LightGBM), tuned via randomized search and combined into a **weighted blend + stacking ensemble**
- **SHAP explainability** — every prediction comes with the top factors driving it, not just a black-box score
- **Business impact translation** — model output converted into revenue-at-risk and campaign ROI, not just accuracy metrics
- **Interactive Streamlit app** with two clearly separated views:
  - 📊 **Explore the Data** — filterable, interactive charts on historical churn patterns
  - 🔍 **Predict Churn Risk** — single-customer lookup and batch CSV scoring, both with SHAP-based reasoning

## 📊 Results

| Metric | Score |
|---|---|
| ROC-AUC (test set) | 0.85 |
| Churn class recall | 0.72 |
| Churn class precision | 0.57 |
| Churn class F1 | 0.64 |

Recall is prioritized over precision on the churn class deliberately: missing an actual churner costs a customer's full future revenue, while a false alarm only costs the price of an unnecessary retention offer.

## 🚀 Getting Started

### 1. Clone the repo
```bash
git clone https://github.com/your-username/customer-churn-prediction.git
cd customer-churn-prediction
```

### 2. Install dependencies
```bash
pip install -r requirements.txt
```

### 3. Get the dataset
Download the [Telco Customer Churn dataset](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) from Kaggle and place the CSV at:
```
data/raw/WA_Fn-UseC_-Telco-Customer-Churn.csv
```

### 4. Run the notebook
Open `churn_model_pipeline.ipynb` and run all cells top to bottom. This trains all four models, builds the blend, evaluates performance, and saves the model artifacts to `models/`.

### 5. Launch the app
```bash
streamlit run app/streamlit_app.py
```
Open the local URL Streamlit prints (usually `http://localhost:8501`).

## 🔍 Key Findings

- **Contract type is the strongest churn driver** — month-to-month customers churn far more than one- or two-year contract holders
- **Payment method compounds contract risk** — Electronic check + month-to-month is the highest-risk combination, and one of the largest customer segments
- **Service bundling reduces churn** — customers with more active add-ons (security, backup, tech support, streaming) are stickier
- **Fiber optic customers churn more** than DSL or no-internet customers, despite being a premium tier — worth investigating for service quality or pricing issues
- Redundant "No internet/phone service" categories were tested and collapsed into "No" — a cleaner encoding with no measurable loss in model performance (ROC-AUC difference: -0.0006, within cross-validation noise)
